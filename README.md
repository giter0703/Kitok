# 키캡 오케스트라

아케이드 푸시 버튼 4개를 키캡 운지 입력으로 쓰는 교육용 음악 웹 프로그램의 작업본입니다.

## 지금 들어 있는 기능

- FastAPI가 웹 화면을 제공하고 WebSocket 연결 상태를 표시합니다.
- STICK S3 물리 버튼 1·2·3·4로 같은 번호의 가상 키캡을 누르고 뗄 수 있습니다. 화면 클릭 시험도 지원하며 A·S·D·F 키보드 입력은 사용하지 않습니다.
- Python 서버가 현재 눌린 조합과 4비트 버튼 마스크를 화면에 돌려줍니다.
- 교사 설정 화면에서 악기를 자유롭게 추가·수정·삭제할 수 있습니다.
- 악기별로 도·레·미·파·솔·라·시의 음높이와 네 버튼 조합을 설정합니다.
- 음높이 목록에서 샵(♯)과 플랫(♭) 표기를 선택할 수 있습니다. 계이름 이름에도 해당 기호를 직접 입력할 수 있습니다.
- 운지표의 계이름 이름을 직접 수정하고 행을 추가·삭제할 수 있습니다. 같은 버튼 조합이 겹치면 중복된 계이름과 버튼 번호를 알려줍니다.
- 시험용 연습곡 **반짝반짝 작은 별** 첫 부분을 80 BPM으로 따라 연주할 수 있습니다. 맞는 운지와 1박·2박 음 길이를 확인합니다.
- 교사용 연습곡 편집기에서 높은음자리표·낮은음자리표와 2/4·3/4·4/4 박자를 설정합니다. 마디줄과 음역에 따른 음표 기둥 방향을 표시합니다. 오선지 입력과 음표 목록 입력을 모두 지원하며, 두 편집 방식은 같은 곡에 즉시 반영됩니다. 음표 메뉴 클릭으로 즉시 추가, 샵·플랫·제자리표, 음 선택·수정·삭제도 지원합니다.
- 곡 편집 화면에서 저장 전에 현재 곡을 미리 재생하고 정지할 수 있습니다. 선택한 악기의 SF2 음색이 준비되어 있으면 해당 음색으로 재생하고, 그렇지 않으면 기본 전자음으로 재생합니다.
- 학생 화면(`/student`, `/`)에서는 연습곡을 선택하고 연주하며, 별도 교사 화면(`/teacher`)에서는 곡을 추가·수정·삭제합니다.
- 학생은 **오선지 작곡·내 작품** 탭(`/student/compose`)에서 오선지로 작품을 작성하고 미리 듣기·임시 저장·교사 제출을 할 수 있습니다. 작곡자 이름 또는 수업용 별명(1~20자)은 필수입니다. 작품 내용은 서버 DB에 저장하며, 브라우저에 보관한 소유 토큰으로 내 작품을 구분합니다. 제출·공개된 작품은 학생이 수정할 수 없습니다.
- 교사 곡 관리의 **작품 보관함**에서 전체·교사 작곡·학생 작곡을 나누어 볼 수 있습니다. 학생 화면의 공개 연습곡 목록도 교사·학생 작곡으로 구분하며 학생 작품에는 작곡자를 표시합니다. 교사가 학생 작품을 공개하거나 수정해도 학생 작품 분류와 작곡자 정보는 유지됩니다. 기존 작품도 저장된 학생 소유 정보에 따라 분류되며 곡과 음표는 변경하지 않습니다.
- 교사는 제출 작품의 오선지 내용을 미리 본 뒤 공용 연습곡으로 공개하거나 수정 의견을 보낼 수 있습니다. 공개된 곡은 학생의 연습곡 선택 목록에 나타납니다.
- 악기와 운지표는 SQLite 데이터베이스에 저장되므로 서버를 다시 켜도 남습니다.
- 교사 설정에서 SF2 또는 DLS 음원을 올리고, 파일 안의 악기 음색을 골라 악기 프로필과 연결합니다.
- 브라우저가 SF2·DLS 음원을 재생하고, 버튼을 누르는 동안 음이 이어지며 놓으면 음이 끝납니다. 음원을 연결하지 않은 악기는 기본 전자음을 사용합니다.
- 업로드한 음원 파일은 프로젝트의 `data/soundfonts` 폴더에 저장됩니다.

## 실행 방법

가상 키캡을 마우스·터치로 처음 누르면 소리가 자동 활성화되어 선택한 악기의 운지표에 해당하는 음을 재생합니다. 단일음과 혼합음 모두 지원합니다. 사용자가 **소리 끄기**를 누른 뒤에는 키캡을 눌러도 음소거를 유지하며, **소리 켜기**로 다시 활성화합니다. STICK S3 입력은 브라우저의 직접 사용자 동작이 아니므로 먼저 학생 화면에서 **소리 켜기**를 눌러야 합니다.

1. VS Code에서 `music-keycap-game` 폴더를 엽니다.
2. VS Code 터미널에서 가상환경을 만들고 활성화합니다.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --reload
```

3. 학생은 `http://127.0.0.1:8000/student`에 접속합니다. 기존 `/` 주소도 학생 화면을 표시합니다. **키 누르기 연습**, **곡 연주**, **오선지 작곡·내 작품** 탭으로 활동을 선택합니다. 키 누르기 연습에서 악기와 소리를 설정하고 가상 키캡으로 버튼 조합을 익힙니다. 곡 연주 탭에는 **곡 따라 연습하기**만 표시하며, 악기·가상 키캡 영역은 숨깁니다. 앞서 선택한 악기와 소리 설정은 유지되며 STICK S3 물리 버튼으로 연주합니다. 탭 전환 시 진행 중인 곡 연주와 누른 음은 초기화됩니다. `/student#play`로 곡 연주 탭을 바로 열 수 있습니다.
4. 교사는 `http://127.0.0.1:8000/teacher`에 접속해 악기를 추가하고 계이름별 음높이와 버튼 조합을 지정합니다.
5. 교사 설정에서 음원 파일을 등록하고 악기 프로필에 음색을 연결합니다.
6. 화면에서 **소리 켜기**를 누른 뒤 악기를 선택합니다. 가상 버튼을 누르고 있으면 음이 나고, 놓으면 멈춥니다. STICK S3 물리 버튼도 같은 가상 키캡과 소리에 연결됩니다.

## 다음 개발 순서

학생 연주·작곡 화면에는 교사 화면으로 이동하는 버튼이 없습니다. 교사는 관리 화면의 **학생 화면 확인 ↗** 버튼으로 학생 화면을 새 탭에 열어 수정 사항을 확인할 수 있습니다. 교사 탭은 그대로 유지되며, 수정 후 학생 탭을 새로고침하면 최신 내용을 확인할 수 있습니다. 현재 교사 주소와 관리 API에 인증은 적용되지 않았습니다. 교사 접근 PIN은 아래 후속 작업입니다.

1. 브라우저 두 개에서 학생 제출과 교사 검토·공개 흐름을 확인합니다.
2. 음원 담당 팀원이 제공하는 SF2/DLS 파일을 받아 업로드·악기 음색 재생을 함께 확인합니다.
3. 아래 STICK S3 연결 방법에 따라 실제 기기에서 무선 입력과 연주 지연을 확인합니다.
4. 수업 환경에 맞춰 교사용 설정 접근 PIN과 학생 작품 보관 방식을 보완합니다.

## STICK S3 물리 버튼 연결

버튼 1~4는 각각 GPIO 3·2·4·5이며 반대쪽 접점은 GND입니다. `device/sticks3_buttons.py`에 UiFlow2 Python 편집기에 복사할 전체 코드가 있습니다. 기존 Wi-Fi와 Access Code 설정을 재설정하지 않습니다.

1. 서버를 프로젝트 폴더에서 외부 접속을 허용하는 주소로 실행합니다. 기존 서버가 같은 포트를 사용 중이면 해당 터미널에서 `Ctrl+C`로 종료한 뒤 실행합니다.

   ```powershell
   D:\musicQ\.verify-venv\Scripts\python.exe -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --reload
   ```

2. PC와 STICK S3를 서로 통신 가능한 같은 내부 네트워크에 연결합니다. 기기는 기존 2.4GHz Wi-Fi를 사용합니다. PC는 같은 공유기의 유선 연결도 가능합니다.
3. `ipconfig`로 PC의 Wi-Fi 또는 유선 LAN IPv4를 확인합니다. 기기 코드의 `SERVER_IP`를 그 주소로 지정합니다. 작성 시 확인한 주소는 `192.168.0.235`이며 DHCP로 바뀔 수 있습니다. `127.0.0.1`이나 `0.0.0.0`은 기기의 접속 주소로 쓰지 않습니다.
4. UiFlow2 Controller에서 **Access Code로 연결된 STICK S3**를 선택하고 `device/sticks3_buttons.py` 전체를 Python 편집기에 복사한 뒤 **Run Once**를 누릅니다. USB는 전원 공급용으로 사용할 수 있습니다.
5. 학생 화면의 **키 누르기 연습**을 열고 기기 버튼을 누릅니다. 물리 1번 → 가상 1번, 2번 → 2번, 3번 → 3번, 4번 → 4번으로 표시되고, 놓으면 해제됩니다. 1+3 동시 입력의 마스크는 5입니다. 학생 화면에서 악기를 선택하고 **소리 켜기**를 눌러야 음이 납니다. 곡 연주 탭에서도 같은 물리 입력으로 연주합니다.

기기 화면의 **WEB OK**는 프로젝트 서버의 응답을 받았다는 뜻입니다. UiFlow2 시작 화면의 SERVER OK와는 별개입니다. WEB NG이면 PC IP·서버 실행 주소·Windows 방화벽의 사설 네트워크 Python 허용 여부를 확인합니다. 학교/게스트 Wi-Fi의 기기 간 통신 차단도 확인합니다. 이 기능을 위해 인터넷 공유기의 포트 포워딩은 필요하지 않습니다.

기기는 하나의 TCP/HTTP keep-alive 연결을 유지하며 `/api/device/input`으로 입력 변경을 즉시 보냅니다. 응답을 기다리지 않는 비차단 송수신으로 버튼 스캔을 계속하고, 유휴 중에는 약 250ms 간격으로 상태를 확인합니다. 서버는 `/ws`로 가상 키캡·소리·곡 연습에 전달합니다. 기기 신호가 약 1.5~1.75초 끊기면 물리 입력을 해제하며, 브라우저 연결이 끊겨도 소리가 멈춥니다. 화면에서 누른 키와 물리 버튼은 함께 반영되므로 한쪽 입력을 놓아도 다른 쪽에서 누른 키는 유지됩니다.

반응 속도를 위해 GPIO 디바운스는 5ms, 스캔 루프 대기는 2ms로 설정하고 LCD 갱신은 약 30Hz로 제한합니다. 지원 펌웨어에서는 Wi-Fi 절전과 TCP 패킷 지연을 끕니다. 연결이 정상일 때 매 입력마다 재접속하거나 응답을 기다리지 않으며, 끊겼을 때만 재연결합니다. 웹은 저지연 오디오 설정을 사용하며, 기본 전자음은 약 3ms 상승·5ms 하강을 적용합니다. 물리/가상 버튼을 놓으면 등록 음원의 긴 릴리스 잔향도 강제 종료합니다. 음원 자체의 어택과 실제 Wi-Fi·스피커 지연은 기기에서 확인해야 합니다. 변경 적용에는 기기 코드 전체 재실행과 웹 새로고침이 모두 필요합니다.

현재는 **한 교실·STICK S3 한 대**를 위한 공용 입력입니다. 같은 서버에 연결된 모든 학생 화면이 물리 입력을 받습니다. 서로 다른 학생에게 별도 기기를 배정하는 기능은 포함하지 않습니다. 서버 중계·가상 키캡 자동 검증은 완료했지만 실제 기기의 Run Once·Wi-Fi 지연은 현장에서 확인해야 합니다.

버튼 프로그램 실행 중에도 화면 하단 **ACCESS CODE**에서 UiFlow2 코드를 확인할 수 있습니다. 공식 시작 화면과 같은 `M5Things.accesscode()`를 읽으며, 1초마다 갱신합니다. `WAIT...`는 아직 코드를 읽지 못한 상태이고, `UNAVAILABLE`은 해당 펌웨어에서 M5Things 모듈을 사용할 수 없다는 뜻입니다. Wi-Fi나 페어링 설정은 변경하지 않습니다. 수정한 코드는 UiFlow2에서 전체 교체 후 Run Once로 다시 실행해야 기기에 적용됩니다.

검증: `python tests/verify_device.py` (임시 DB와 실제 HTTP/WebSocket·브라우저 사용).

STICK S3 화면의 `BAT: 75%`는 배터리 잔량이며 시작 시 한 번 읽고 이후 10초마다 갱신합니다. 충전 중이면 `CHG`가 붙습니다. 표시 내용이 바뀔 때만 화면을 갱신합니다. 잔량을 읽을 수 없으면 `BAT: --`를 표시하며 버튼 연동은 계속됩니다. 배터리 표시는 기기의 추정값입니다. Access Code와 버튼 상태도 같은 화면에 유지됩니다.

## 현재 단계의 범위와 저장

- 교사 설정 화면은 악기 이름, 분류, 아이콘, 도~시 음높이, 네 버튼 조합을 관리합니다.
- 네 버튼으로 15가지 조합을 만들 수 있으며, 버튼을 모두 놓으면 쉼으로 표시합니다.
- 음원 파일은 저작권과 사용 조건을 확인한 뒤 등록합니다. 합성 라이브러리는 웹 폴더에 포함되어 있어 Node.js 설치 없이 실행할 수 있습니다.
- 음원 파일은 SF2 또는 DLS 형식이며 100MB까지 등록할 수 있습니다. 실제 음색 재생은 적합한 음원 파일을 교사가 등록한 뒤 사용할 수 있습니다.
- 브라우저 음원 합성 라이브러리와 사용권 전문은 `web/vendor` 폴더에 포함됩니다.
- 기존 데이터베이스가 초기 프로토타입 구조라면 서버 시작 시 새 악기 설정 구조로 자동 갱신합니다. 프로필 정보는 유지하고 이전 운지표는 초기화됩니다.


## 단일음·혼합음 운지 설정

- 교사 화면 → 악기·운지표에서 각 운지 행의 음높이는 기본 한 개입니다. **＋ 혼합음 추가**를 누르면 같은 버튼 조합에 음높이를 최대 4개까지 지정할 수 있습니다. 추가한 음 옆의 **−** 버튼으로 제거하면 다시 단일음으로 사용할 수 있습니다.
- 예: 계이름 이름을 `도·미`, 음높이를 `C4`와 `E4`, 버튼을 `1`과 `3`으로 지정하고 악기를 저장합니다. 학생이 1번과 3번을 함께 누르면 두 음이 동시에 나며 놓으면 멈춥니다. 이미 같은 조합의 운지 행이 있다면 그 행을 수정해야 합니다.
- 혼합음은 지정된 조합 전체에 대응합니다. 개별 버튼의 음들을 자동 합산하는 방식은 아닙니다. 기존 단일음 설정은 유지되며 혼합음도 서버 재시작 후 유지됩니다. 기본 전자음과 SF2/DLS 음색에 적용합니다.
- 현재 곡 작곡·따라 연습은 단일음 악보를 사용하므로, 혼합음 운지는 단일음의 정답 운지에서 제외합니다.
- 혼합음 회귀 검증: `python tests/verify_chords.py`. 임시 DB에서 저장·교사 편집·전자음 동시 재생과 종료를 검사하며, 음원 합성 연결은 테스트 대역으로 MIDI 시작·종료 호출을 확인합니다.

## 기본·심화 작곡 도구 사용

- 학생·교사 오선지는 박자표에 맞춰 2/4는 2박, 3/4는 3박, 4/4는 4박씩 한 마디에 배치합니다. 마디가 끝나면 다음 마디로 이어지며 줄바꿈은 마디 사이에서만 합니다.
- 마디를 넘는 음표는 마디 안에 들어가는 길이로 나누어 붙임줄로 연결하고, 쉼표도 마디 경계에 맞춰 나누어 표시합니다. 나뉜 음표를 선택하면 원래 음의 음높이·전체 길이를 편집합니다. 저장된 곡의 음높이와 전체 길이, 미리 듣기는 그대로 유지됩니다.
- 마디 번호와 마지막 마디의 남은 박자를 표시합니다. **남은 마디 쉼표로 채우기**를 누르면 부족한 길이만큼 쉼표를 추가합니다. 미완성 마디도 저장할 수 있습니다.

- 교사 설정 → 곡 관리 → 오선지 편집기에서 **심화 도구 사용**을 켜거나 끕니다. 설정은 서버에 저장되며 학생·교사 편집기에 공통 적용됩니다. 다른 기기는 최대 5초 후 반영됩니다.
- 기본: 온·2분·4분·8분음표와 각 쉼표. 심화: 16분음표, 점2분·점4분·점8분음표와 각 쉼표가 추가됩니다.
- 음표·쉼표 메뉴를 클릭하면 곡 끝에 바로 추가됩니다. 연속 클릭으로 여러 음을 추가합니다. 추가된 음을 선택하고 오선지를 눌러 음높이를 바꾸며, 길이와 쉼표 여부는 목록에서 수정합니다.
- 심화를 꺼도 기존 음표는 유지됩니다. 32분·64분·겹온음표는 새 도구에 없으며, 기존 데이터만 보존합니다. 목록의 `기존 길이 (보존)` 선택지가 이를 표시합니다.
- 미리 듣기는 점음표와 16분음표의 길이를 반영하고, 쉼표 동안은 소리 없이 진행합니다.
